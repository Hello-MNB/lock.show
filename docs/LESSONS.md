## 2026-07-21 · The embed shipped with committed git conflict markers (P0, live ~3 days)
**What happened:** the 18 Jul train merge (`5617896`) claimed "embed conflicts resolved" but committed raw `<<<<<<< HEAD`/`>>>>>>>` markers into all 34 `website-next/public/app/**/index.html` files + both CSS heads. Browsers reparent stray head-text into the body, so every lock.show/app screen rendered conflict markers as visible "developer text", and BOTH merged script tags booted two React bundles that fought over #root → ErrorBoundary "Something went wrong" on login/signup. Nobody caught it because witness walks used app.lock.show and previews (built from src/), never the committed embed mirror; an external audit caught it on the live domain.
**Root failures:** ① a merge resolved binary-ish build artifacts by hand instead of rebuilding them; ② no machine gate scanned the committed embed; ③ the embed mirror surface wasn't in any walk path.
**Rules now standing:** ① embed conflicts are NEVER hand-resolved — regenerate with `npm run build:embed` from the intended source and recommit; ② `test:embed` (scripts/test-embed-integrity.mjs) is in the verify chain — conflict markers or double-bundle heads in the committed embed FAIL the build; ③ any train that ships lock.show must curl-verify `/app/login` for marker count 0 before reporting live.
