## 3 Interaction-pattern justification (no defaults)
- Tabs = stable sibling views of one object. Filters = same collection, subset. Segmented = view mode.

## Amendment I — Show, don't explain (build gate)
A screen states its conclusion ONCE, then shows. If understanding requires a second sentence, the LAYOUT failed — fix is structural, never more copy. Rules: (1) one conclusion line of chrome per screen; (2) disclaimers become visual states (dashed container + mono chip, e.g. SAMPLE), never captions; (3) method/limitation/provenance live one tap down (PAT-KNOWN drawer) — trust preserved, surface calm; (4) thin/empty state is the DEFAULT design target, not the 25-year-act footprint; (5) density per persona profile — strip Artist+Recipient hard, keep Show-Day rich. Acceptance: every screen passes the 5-second test with zero explanatory clauses on claim rows.

## Amendment J — SSOT transition + audit cap
(1) The prototype is the design truth ONLY until the first persona package ships to Claude Code; from that moment the implementation + Design System become truth and the prototype demotes to reference — this transition must be declared explicitly, never assumed. (2) Audit cap: one consolidated freeze pass per persona, then STOP auditing that persona — further polish waves require a real-user finding, not an internal reviewer. Rationale: the audit loop is the named avoidance pattern; validation (a real booker reaction) unlocks further breadth, not another sweep.
