# LOCK.SHOW — Entity Screen Blueprints (v1 · 9 Aug 2026)
Screen grammar per entity — everyday design reference. Not page templates.

## 1 · ARTIST — Reflective Intelligence
**A. Mental model:** understand my professional standing → decide one move → strengthen my story. **B. Hierarchy:** Conclusion → why it matters → one Next Move → my world → detail/source. **C. First viewport 390:** shell + conclusion sentence + Next Move CTA; universe begins at fold. **D. Archetypes:** Explore, Workbench (category), Collection→Composer→Preview→Decision (passport), Work Queue (inbox). **E. Navigation:** 3 roots (Radar·Passport·Inbox); category = full workspace; source detail = sheet; act switch = overlay; scan = wizard. **F. Density:** low-medium; one idea per band. **G. Visuals:** universe map, trajectory line, media rail, diff; never admin tables. **H. Metadata priority:** claim state (confirmed/candidate/stale), source+method+date, visibility, passport impact. **I. CTA verbs:** Review · Confirm · Correct · Strengthen · Publish · Share. **J. Assets:** "your current rider/plot/footage" — personal possessions with freshness, one-tap refresh. **K. States:** Waiting = calm ("with the station now"); Stale = nudge, never alarm; Conflict = "needs your decision". **L. Mobile:** sources collapsed by default; sticky = one CTA max; planets grid 2-col. **M. Desktop:** universe + inspector side-by-side. **N. Anti-patterns:** CRM feel, leaderboards, percentages as grades, moderation-queue vocabulary.

## 2 · REPRESENTATION — Commercial Editorial
**A. Mental model:** scan the roster → prioritise → prepare the pitch → move the deal. **B. Hierarchy:** what needs me → commercial context → artist/opportunity → next move. **C. First viewport:** greeting + "3 need your attention" + first attention card. **D. Archetypes:** Command+Intelligence (overview), Directory (artists), Management (access), Detail w/ siblings (artist workspace), Case (opportunity). **E. Navigation:** roots Roster·Opportunities·Inbox; Roster local tabs Overview·Artists·Access; artist workspace = anchored sections; case = workspace (never sheet); capture/contact = sheets. **F. Density:** medium-high acceptable. **G. Visuals:** roster movement trend, territory footprint, requirement-vs-record matrix, media-led artist cards. **H. Metadata:** mandate scope+expiry, passport per-recipient state, opportunity stage+waiting-on, sellable formats. **I. CTAs:** Pitch · Prepare · Renew · Approve · Send · Follow up · Handoff. **J. Assets:** "pitch materials" — currency of the trade; version + recipient eligibility visible. **K. States:** Waiting shows WHO has the ball; Expiring = amber with days; never red for stale. **L. Mobile:** rich cards; desktop rows+preview pane at 40+ acts; conversation = desktop supporting pane. **M. Desktop:** two-pane prepare+conversation. **N. Anti-patterns:** finance ERP, artist leaderboards, probability scores.

## 3 · PRODUCTION — Live Operations
**A. Mental model:** monitor → coordinate → resolve → deliver the show. **B. Hierarchy:** NOW → NEXT → what can still change the show → owner → detail. **C. First viewport:** next show hero (days to doors) or LIVE banner + first cue. **D. Archetypes:** Intelligence (growth), Directory (events), Operational Detail (event workspace), Timeline (line-up), Workbench (advance), Live takeover (show day). **E. Navigation:** roots Growth·Events·Inbox; event = one workspace (Overview points, Line-up owns slots, Advance owns delivery); routine slot = sheet; decide/compare = full screen; Show Day = mode. **F. Density:** high when show-critical. **G. Visuals:** stage lanes, running order, countdown, dependency rows, calendar tiles, versioned assets. **H. Metadata:** time/stage/duration/changeover, owner per item, waiting-on, asset version vs reviewed version. **I. CTAs:** Lock · Confirm · Resolve · Circulate · Advance · Enter Show Day. **J. Assets:** event references artist-owned versions ("Fusion reviewed v3 · artist uploaded v4"). **K. States:** Live = lime signal; Delayed = time-shift not blame; Issue = owner + next action. **L. Mobile:** lanes scroll horizontally; NOW/NEXT/ISSUES only in live first viewport. **M. Desktop:** multi-stage lanes side-by-side. **N. Anti-patterns:** PM-SaaS task cards, financial reporting, celebration noise during live ops.

## 4 · RECIPIENT — Curated Stage
**A. Mental model:** understand the act → evaluate fit → act once. **B. Hierarchy:** artist → relevance to ME → representative media → decision info in my order → one CTA. **C. First viewport:** artist identity + relevance statement + first media edge. **D. Archetypes:** Editorial (one renderer, six decision policies). **E. Navigation:** none; anchor nav collapsible, one sticky commercial CTA. **F. Density:** low; premium whitespace. **G. Visuals:** full-bleed media, method-labelled facts, quiet chips. **H. Metadata:** what proves the decision (formats, live history, tech pack availability) — never internal gaps/percentages. **I. CTAs:** Check availability · Request production details · Discuss representation (one per view). **J. Assets:** playable/preview-first; "available on request" for restricted. **K. States:** dead link = 6 warm distinct states; nothing exposes internals. **L. Mobile:** media dominates; chrome minimal. **M. Desktop:** wider editorial grid, same policy. **N. Anti-patterns:** app chrome, workspace vocabulary, view-switcher exposure, metric dumps.

## 5 · ADMIN — Operational Governance
**A. Mental model:** detect exception → understand consequence → intervene safely → audit. **B. Hierarchy:** what needs judgment → consequence → bounded action → trail. **C. First viewport:** gate signals + first exception. **D. Archetypes:** Governance queue. **E. Navigation:** Operations-first; diagnostics behind it. **F. Density:** dense, calm. **G. Visuals:** structured tables, threshold chips, audit lists. **H. Metadata:** scope, affected entity, automation action already taken, reversibility. **I. CTAs:** Quarantine · Request review · Keep separate · Re-auth · Dismiss with reason. **J. Assets:** n/a (references only). **K. States:** every exception shows what automation already did. **L/M:** table-first, mobile = stacked rows. **N. Anti-patterns:** executive dashboards, editorial storytelling, raw error codes.
